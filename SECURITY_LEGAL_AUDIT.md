# SECURITY_LEGAL_AUDIT

Audit scope: repository at commit `6dafa49` (origin/main), static source review, dependency metadata, and repository history. No code was changed for this audit.

## Security

1. API keys not in client code or git history — PASS. Client components do not reference `GITHUB_CLIENT_SECRET`, `GEMINI_API_KEY`, or `GITHUB_COOKIE_KEY`; `src/components/MiniIDE.tsx` only calls first-party API routes. `git log --all -- .env` returns no commits, and `git log -S` for key patterns returns only code/config references, not secret values.
2. Environment variables: `.env.example` only, `.env` gitignored — PASS. `.env.example:1-7` documents required server variables; `.gitignore:7-9` ignores `.env` and `.env.*` while allowing `.env.example`.
3. Admin/protected routes — N/A (no admin role system). Protected GitHub workflows require a decrypted session and return 401 without one; see `src/app/api/github/[action]/route.ts:271-280`, `389-392`, `408-415`, `821-828`, `888-891`, `1088-1094`, and `1196-1213`.
4. Authentication (GitHub OAuth) — PASS. State is generated with `randomBytes(32)` and compared at `src/app/api/github/[action]/route.ts:190`; PKCE verifier is checked at line 210. Session/flow cookies are set with `httpOnly: true`, `sameSite: "lax"`, `secure` in production, and `path: "/"` at lines 144-149 and 256-261. `GITHUB_COOKIE_KEY` is required to decode to exactly 32 bytes and is used for AES-256-GCM at lines 34-76.
5. Authorization on `/api/github/*` — PASS. Every GitHub data/action handler decrypts and validates the session before use; `publishPullRequest` and `importPrivateRepository` also enforce `Origin` equality at lines 390 and 404. Repository identity, paths, and imported-path baselines are validated at lines 444-575.
6. Input validation/sanitization on route handlers — PASS (per-route, no shared schema). Examples: `src/app/api/analyze/route.ts:7-16` validates file count, path, content, and totals; `src/app/api/github-import/route.ts:9-12` validates URL and body size; `src/app/api/preview/proxy/route.ts:146-241` validates content type, payload, target, method, headers, and body.
7. XSS (`dangerouslySetInnerHTML`, preview injection) — PASS for app code, with one intentional use. `src/app/(public)/page.tsx:97` uses `dangerouslySetInnerHTML` only with `JSON.stringify(jsonLd)`. Preview HTML is generated by `buildPreview` in `src/lib/ideCore.ts`; the analyzer also flags raw HTML rendering (`src/lib/analyzer.ts:32`).
8. Rate limiting on every route — FAIL. Only `src/app/api/preview/proxy/route.ts:37-54` has a rate bucket. `/api/preview/ai` has a 5-second cooldown (`src/app/api/preview/ai/route.ts:94-103`), but `/api/preview/gateway`, `/api/preview/health`, `/api/analyze`, and `/api/github/*` have no rate limiting.
9. API endpoint security (`/api/analyze`, `/api/github-import`) — PASS. `/api/analyze` validates JSON and file limits; `/api/github-import` validates repository URLs and body size. Both use `nodejs` runtime and return generic errors.
10. CORS settings — PASS (intended). `src/app/api/preview/proxy/route.ts:115-123` returns `Access-Control-Allow-Origin: *`, but POST rejects any non-null `Origin` at lines 130-136, so the wildcard is effectively limited to the preview sandbox.
11. Security headers — FAIL. `next.config.ts:12-18` sets 4 headers (nosniff, referrer policy, X-Frame-Options, permissions policy) but no Content-Security-Policy or HSTS. `X-Frame-Options: SAMEORIGIN` is compatible with the same-origin `srcdoc` preview iframe.
12. Debug mode / verbose errors in production — PASS. `/api/preview/ai`, `/api/preview/gateway`, and `/api/preview/health` return 404 outside development (`src/app/api/preview/ai/route.ts:20-24`, gateway lines 101-105, health lines 7-11). Route handlers return generic messages and do not expose stack traces.
13. Outdated dependencies — FAIL. `npm outdated` reports newer major versions for `next` (15.5.28 -> 16.4.5), `lucide-react` (0.468.0 -> 1.69.0), `typescript` (5.9.3 -> 7.0.2), `@types/node`, `@types/vscode`, and `@vscode/vsce`.
14. Unused packages — PASS (manual review). Runtime dependencies (`next`, `react`, `react-dom`, `monaco-editor`, `@monaco-editor/react`, `lucide-react`) are imported by application code. Development dependencies support type checking, builds, tests, and extension packaging.
15. Exposed files — FAIL. `public/__qa/responsive.html` is a QA harness served from the public directory, and `reports/` contains internal QA/release artifacts. `reports/qa/desktop-assets-recovery-d813de3.jpg` and `reports/upstream-2026-11-02/*` are tracked. Root-level `PATCH_*.md`, `BASELINE_REPORT.md`, `RELEASE_REPORT.md`, and `RUNTIME_PLAN.md` are also internal-facing.
16. Database — N/A. No server-side database or ORM is used. The only storage is browser IndexedDB for workspace drafts (`src/lib/workspaceDraft.ts:29`).
17. Password hashing — N/A. Authentication is GitHub OAuth only; the application does not store passwords.
18. Secrets in git history — PASS. No `.env` file appears in history (`git log --all -- .env` is empty). `git log -S` for key patterns returns commits that use environment variables, not secret values.
19. `npm audit` summary — FAIL (8 vulnerabilities: 1 critical, 3 high, 3 moderate, 1 low). Direct dev dependency `@vscode/vsce` is affected via `minimatch`; `next` is affected via `postcss`; transitive `@azure/msal-node`/`@azure/identity` and `dompurify` (via monaco) are also reported. None of the direct runtime app dependencies are flagged except through `next`.
20. SSRF review of proxy and github-import — PASS. The proxy allows only HTTPS public hosts and blocks private/local addresses, credentials, and the FORGEX origin (`src/app/api/preview/proxy/route.ts:78-113`, 91-111). Redirects are revalidated at lines 257-274. `githubImport.ts` only fetches `https://api.github.com` for a validated owner/repo and blocks `.env` paths.

## Legal / Privacy

- Privacy page and terms page exist — PASS. `src/app/(public)/privacy/page.tsx` and `src/app/(public)/terms/page.tsx` describe GitHub OAuth, cookies, proxy/API requests, browser storage, retention, and support contact.
- Match to app behavior — PASS with one caveat. The pages cover GitHub import/publish, Gemini, Open-Meteo, and browser storage. `src/app/(public)/privacy/page.tsx:123-128` states that logging configuration and retention must be confirmed before production release.
- Cookie consent need — PASS/N/A. Only an essential authenticated session cookie is used; no analytics or advertising trackers were found in `src/app/layout.tsx` or public pages.
- Data collected — PASS (documented). Local workspace files and drafts may be stored in the browser; GitHub data is accessed only when connected; approved AI/weather requests send the submitted prompt/coordinates.
- Data deletion/contact route — PARTIAL. `src/app/(public)/privacy/page.tsx:189-203` provides an email contact route, and browser data can be cleared locally. There is no automated account/data deletion endpoint; GitHub access must be revoked in GitHub settings.
- Refund policy — N/A. The app is free; no payments are implemented.
- Third-party SDKs and fonts — PASS. Google Fonts are loaded through `next/font/google` (`src/app/layout.tsx:3`) and self-hosted at build time. Icons are bundled from `lucide-react`. No runtime font CDN is used by the app shell.
- Font/image licenses — PASS (reviewed at a high level). Brand assets are first-party files in `public/brand`; Google Fonts are licensed for self-hosting. No third-party image assets with unclear licenses were found.
- Accessibility — PARTIAL. Decorative images use `alt=""`, and `ImageViewer` uses the file path as alt text (`src/components/ImageViewer.tsx:47`). No formal color-contrast or keyboard-navigation audit was performed in this pass.
- No fake reviews or unsupported claims — PASS. Public pages describe features and limitations; no testimonials, ratings, or unsupported performance claims were found.
- Business/contact details present — PASS. `src/lib/siteInfo.ts:4-6` provides support email, WhatsApp, and company URL; both legal pages display the support email.
- Age consent — N/A. The service is not targeted at children.

## Prioritized fix list

1. Add rate limiting to all state-changing and external-provider routes, especially `/api/preview/ai`, `/api/preview/gateway`, `/api/preview/health`, `/api/analyze`, and `/api/github/*`.
2. Add a Content-Security-Policy and HSTS in `next.config.ts`, while preserving the same-origin preview iframe behavior.
3. Remove or gate internal QA/report artifacts (`public/__qa`, `reports/`, root-level patch/report markdown) so they are not shipped or exposed.
4. Update vulnerable/outdated dependencies, prioritizing `next`/`postcss`, `@vscode/vsce`, and transitive `dompurify`/`minimatch`.
5. Add an automated or documented data-deletion request flow and confirm production logging/retention settings.
6. Complete a formal accessibility audit for contrast and keyboard navigation.
7. Keep the preview proxy's SSRF and origin-null checks as-is; they are a good baseline.

## Top 5 fixes

1. Rate limiting on every route (highest abuse/DoS risk).
2. Content-Security-Policy and HSTS headers.
3. Remove exposed internal QA/report artifacts.
4. Dependency vulnerability updates (npm audit).
5. Data deletion/contact and production logging confirmation.
